# Vizoalica v0.5.1 — Project-first website setup

**Deployment support**: fresh deployments only. Apply the complete migration baseline to a new,
empty D1 database. This release does not upgrade or preserve an existing Vizoalica database.

**Compatibility**: no breaking analytics, ingestion, or static-snippet contract changes. Existing
static installations remain supported, and dynamic configuration is an additive option.

Vizoalica 0.5.1 makes projects a primary console destination and requires an explicit project when
registering a website. Installation guidance now offers the existing static snippet alongside a
provider-neutral dynamic loader. For Cloudflare Pages, the release includes a configuration
Function, public-variable mapping, generic loader asset, reviewed command sequence, and local or
post-deployment verification guidance.

The console also explains the Local workspace trust boundary and uses a centered, non-obscuring
footer with the product website, GitHub repository, current year, and build version.

The release was validated with formatting, lint, type checking, 445 unit and integration tests,
95.83% line coverage, 90.07% branch coverage, production builds, 11 Chromium responsive and
accessibility scenarios, a production dependency audit, and a local Cloudflare Pages Functions
compile and configuration-response exercise.

This release does not contain Cloudflare account credentials and does not trigger deployment. A
self-hosting operator decides whether and when to deploy it.

See the [changelog](../../CHANGELOG.md), [release operations](../operations/releases.md),
[Cloudflare installation guide](../operations/cloudflare.md), and
[Pages website guide](../operations/pages.md) for details.
