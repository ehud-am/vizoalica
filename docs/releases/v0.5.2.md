# Vizoalica v0.5.2 — Quality and simplicity

**Deployment support**: fresh deployments only. An existing 0.5.1 database needs one manual
`ALTER TABLE` statement first; see the changelog upgrade notes.

**Compatibility**: no breaking analytics or static-snippet changes. Ingest requests without a valid
token now return 401 before any lookup, including for unknown source keys (previously 403).

Vizoalica 0.5.2 replaces the manual website deployment commands with a reusable GitHub Actions
workflow. A push to a customer's website repository deploys the site and the Vizoalica Functions
to Cloudflare Pages, with all analytics configuration coming from repository variables and secrets
rather than committed source. The console leads with that path and shows whether the website's
configuration endpoint is reachable. Operators can now delete a project from the console.

The release also closes real defects found in review: soft-deleted websites and projects kept
accepting events, and the daily retention job could not keep up with steady traffic, letting D1
grow without bound. It adds an opt-in ingest rate limiter and rejects unauthenticated requests
before any database read.

One risk is accepted rather than fixed: `VIZOALICA_TOKEN_SECRET` is shared by every website on a
backend, so treat it like the administrator secret. See the security findings for the reasoning.

The release was validated with formatting, lint, type checking, production builds, 480 unit and
integration tests, 95.86% line coverage, 90.54% branch coverage, and a production dependency audit.
It does not contain Cloudflare credentials and does not trigger deployment.
