# Vizoalica v0.13.0: no-script pixel

**Deployment support**: D1 migration `0008_pixel_page_views.sql` (one column with a default, additive). The backend
(Worker) and the console changed. Update a running backend with `vizoalica deploy <name> --update`, or all of
them with `vizoalica deploy --update --all`. The browser SDK is unchanged.

On top of [v0.12.1](v0.12.1.md):

- **Count views of a README.** A new image route, `GET /v1/pixel.gif?website=<website-key>&path=/npm/vizoalica`,
  records one page view and returns a 1x1 GIF with `Cache-Control: no-store`. Put it in a GitHub or npm README as
  a Markdown image. See [Count views of a README](../operations/pixel.md).
- **Off by default, per website.** An image request carries no origin, so hits can be forged. Switch it on in the
  console (website → **Edit**) or with `pixelEnabled` on the admin API. Pixel views are marked `pixel` in the raw
  event archive. Excluded addresses and quotas apply as for any event.
- **Same counting as the script.** Unique visitors use the daily salted digest; nothing is stored in the browser.
- **READMEs fill the pixel from the pipeline.** A block between `<!-- readme-pixel:start -->` and
  `<!-- readme-pixel:end -->` is filled from the public variables `VIZOALICA_INGEST_ENDPOINT` and
  `VIZOALICA_README_WEBSITE_KEY` (or `VIZOALICA_WEBSITE_KEY`): by a workflow for the repository README, and at build
  time for the npm README. Empty when unset.
- **Known limits.** GitHub and npm proxy images, so counts there are rough and unique visitors cannot be told
  apart; referrers are generic (use a distinct `path` per README); blockers may drop the image. See the
  [privacy review](../privacy/pixel-review.md).

## Install or update

```sh
npm install -g vizoalica      # or: npm update -g vizoalica
vizoalica --version           # 0.13.0
vizoalica deploy --update --all
```
