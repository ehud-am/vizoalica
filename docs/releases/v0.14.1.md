# Vizoalica v0.14.1: pixel path slots free themselves

**Deployment support**: one additive database migration (`0010_pixel_path_expiry.sql`, schema 10). Update each
backend with `vizoalica deploy <name> --update`. Until then a Worker keeps working and the pixel path limit behaves
as in v0.14.0 (slots are not freed).

On top of [v0.14.0](v0.14.0.md):

- **Pixel path slots expire** ([#86](https://github.com/ehud-am/vizoalica/issues/86)). A path not seen for 32 days is
  removed by the daily cleanup and its slot is free again, so made-up or renamed paths cannot fill a website's
  limit for good. See [Count views of a README](../operations/pixel.md).
- **Privacy review** ([#87](https://github.com/ehud-am/vizoalica/issues/87)) for goals, grouping rules and pixel
  paths, with a retention statement for each:
  [Goals, grouping and pixel paths review](../privacy/goals-grouping-pixel-paths-review.md).
- **Goals polish** ([#88](https://github.com/ehud-am/vizoalica/issues/88)). The 20-goal limit holds when requests
  arrive together. Page goals and grouping patterns that could never match are refused with a clear error. The goals
  panel shows a retryable error when loading fails instead of claiming the backend is old.
- `VIZOALICA_PIXEL_MAX_PATHS` with an invalid value is ignored instead of stopping the Worker.

## Install or update

```sh
npm install -g vizoalica      # or: npm update -g vizoalica
vizoalica --version           # 0.14.1
vizoalica deploy <name> --update   # for each backend
```
