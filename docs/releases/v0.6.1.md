# Vizoalica v0.6.1 — Actions are attributed to the page they were clicked on

**Deployment support**: no D1 schema change and no backend change. Rebuild the SDK
(`pnpm browser-sdk:build`) and copy `vizoalica.js` to each website that already runs 0.6.0.

**Compatibility**: none broken. The generated website-workflow reference now points at `v0.6.1`.

Vizoalica 0.6.0 attributed a click on a link to the wrong page on sites whose router handles the
click itself (VitePress, and many single-page frameworks do): the router had already navigated by the
time the SDK read the address, so a click on "Tour" was recorded on `/tour` instead of the page it was
clicked on. The link and its destination were right; only the page was wrong. Found on vizoalica.dev
right after 0.6.0 was published.

The SDK now reads the page when the press begins (pointer down, or the key that activates a control),
which always happens before any router acts on the click, and uses it for the action. A click with no
preceding press (a script calling `click()`) falls back to the current page. Page views were not
affected.

If you updated a website to 0.6.0, update its SDK file to 0.6.1. Actions recorded by 0.6.0 on such
sites keep the page they were recorded with, and expire after 32 days like everything else.
