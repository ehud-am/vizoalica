# Vizoalica v0.12.0: rage clicks

**Deployment support**: D1 migration `0007_rage_click_reports.sql` (two tables, additive). The backend (Worker)
changed. Update a running backend with `vizoalica deploy <name> --update`, or all of them with
`vizoalica deploy --update --all`. Update the backend before bundling the new `@vizoalica/browser-sdk`: a backend
older than this release rejects the new burst events, but only those; page views and ordinary clicks still
arrive. Websites that load the SDK from their own backend are unaffected.

On top of [v0.11.1](v0.11.1.md):

- **Rage clicks report.** The console has a **Rage clicks** page and the MCP server a `get_rage_clicks` tool: the
  buttons and links that visitors click 3 or more times within a second, with bursts over time and, per control,
  its page, bursts, all clicks, and bursts per click. Filter by page or action in the tool. See
  [Rage clicks](../operations/rage-clicks.md).
- **How it is detected.** In the browser, on the clicks the SDK already observes: mouse and touch only (a held
  key never counts), at most one burst per control every 5 seconds and 20 a minute per page load. The burst is one
  extra event flagged `rage: true` and does not add to the click counts.
- **What is stored.** A count per minute, page, and control. No visitor identifier, no session, no click
  position. See the [privacy review](../privacy/rage-clicks-review.md).
- Only bursts received after the update are counted; the report says so when the chosen range starts earlier.
- Dead clicks (a click with no visible response) are not part of this release.

## Install or update

```sh
npm install -g vizoalica      # or: npm update -g vizoalica
vizoalica --version           # 0.12.0
vizoalica deploy --update --all
```
