# Vizoalica v0.9.1: Access keys page, easier deploys

**Deployment support**: no database migration. The backend (Worker) changed: key rename and rotate endpoints.
Update a running backend with `vizoalica deploy <name> --update`, or all of them with
`vizoalica deploy --update --all`.

On top of [v0.9.0](v0.9.0.md):

- **Access keys page.** A website's page has an **Access keys** card and button that open a full page listing
  keys by name and role (admin, website owner, analyst), with Create, Rename, Rotate, and Delete. The built-in
  Admin key is listed and cannot be deleted there, so deleting keys never locks you out. Key values are shown
  only once, at creation. This replaces **Share setup**.
- **Ingestion endpoint on the website page.** The Details card shows it with a copy button.
- **Version in the console.** The footer shows `Vizoalica vX.Y.Z`, and the backend version when it differs.
- **Sign in to Cloudflare in your browser.** `vizoalica env add` and `vizoalica deploy` offer browser sign-in
  (default) or a pasted API token with a pre-filled token link. `--cloudflare-login` skips the question.
- **`vizoalica deploy --update --all`** updates every environment you administer, stopping at the first failure.
- **One vocabulary** in the console, CLI, README, and docs: project ID, website ID, website key, ingestion
  endpoint, backend address, token endpoint, admin key, access key.
- **Fixed**: from a source checkout, `deploy` and `env add` now build the Worker files and database changes on
  every run instead of shipping whatever was built last. The npm README and homepage no longer describe the
  removed "save two secrets" step.
- **Security**: dependency updates, including `@modelcontextprotocol/sdk` 1.32.1 (GHSA-6qxp-vccf-f47h) and
  `source-map-js` 1.2.2 (GHSA-68fv-2mgg-jv7q).

## Install or update

```sh
npm install -g vizoalica      # or: npm update -g vizoalica
vizoalica --version           # 0.9.1
vizoalica deploy --update --all
```
