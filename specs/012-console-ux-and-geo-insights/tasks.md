## Implementation notes (deviations from the plan)

- T001: the country reference data comes from `countries-list` and `i18n-iso-countries` (both MIT)
  instead of `world-countries` (ODbL share-alike), to keep the repository MIT-clean.
- T015: no `HelpMenu.tsx`; the existing `WorkspaceContextHelp` became the single help location.
- T036: Pages, Sources, Technology, and Traffic quality live in one file, `analytics/ListPages.tsx`.
- T021 and T010: the capability checks are in `area-separation.test.tsx` and the router and dialog
  tests are `router.test.tsx` and `confirm-dialog.test.tsx`.
- T029 and T045: automated accessibility checks run in Playwright (axe, light and dark, every
  route); jsdom tests assert names, roles, and focus behavior.
- T047: docs are checked by `apps/admin-web/tests/docs-links.test.ts`.
- The docs contract test `apps/deploy-cli/tests/contract/deployment-docs.contract.test.ts` now
  expects the README's `## At a glance` heading (the README edit from the docs branch).

- US3 (Phase 4) needs only Phase 2 and Phase 3 shell; T022 and T023 (Worker) are independent of the console tasks.

## Implementation Strategy

1. **MVP**: Phases 1 to 3 (shell, separation, scope) and Phase 4 (Geography), since both are P1.
2. Then Phase 5 and Phase 6 (P2), then Phase 7, then Phase 8.
3. Keep the console working after every phase: existing pages stay reachable under the new routes
   until their replacements land, and full gates run at the end of each phase where practical.
4. Do not commit, push, merge, tag, or release. Leave all changes in the working tree for the
   owner's pre-release testing.
