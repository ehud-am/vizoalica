# Quickstart Validation: Separate Deployment Journeys

This guide validates the implementation without creating or modifying real customer cloud
resources. Human live-deployment checks remain approval-gated and are not part of automated
validation.

## Prerequisites

- Node.js 22 or newer
- pnpm 9 with dependencies installed
- SQLite command-line client for the focused baseline smoke test, when available

## 1. Verify the feature artifacts

```sh
.specify/scripts/bash/check-prerequisites.sh --json --require-tasks --include-tasks
```

Expected: the active feature directory is `specs/009-separate-deployment-journeys` and all design
artifacts plus `tasks.md` are listed.

## 2. Verify the fresh baseline

```sh
find deploy/cloudflare/migrations -maxdepth 1 -name '*.sql' -print
```

Expected: exactly `deploy/cloudflare/migrations/0001_initial.sql`.

Run the focused baseline/preflight tests generated by the implementation tasks. Expected:

- the baseline applies to an empty database;
- all current tables, columns, indexes, and constraints exist;
- upgrade-only rename/backfill statements are absent;
- empty schema inspection passes;
- existing or ambiguous schema inspection fails before mutation.

## 3. Verify the four journeys

Read the README selection table, then validate each guide independently:

1. US1: start with only a fresh cloud account and customer administrator prerequisites.
2. US2A: start with only a verified backend handoff and direct administrator credential access.
3. US2B: start with only a verified backend handoff and an authorized OneCLI environment.
4. US3: start with only the backend/operator handoff and control of one website.

Expected: each guide contains its scope/frequency, inputs, security boundary, all required actions,
checks, handoff, and recovery/removal guidance. No required step is hidden only behind a link.

## 4. Run repository validation

```sh
pnpm format:check
pnpm lint
pnpm validate
pnpm build
pnpm coverage
```

Expected: all checks pass and repository-wide line and branch coverage remain above 90%.

## 5. Human checks before release

- A new customer can identify the correct story and frequency from the README in under 60 seconds.
- A first-time operator can complete US2A or US2B within 20 minutes after prerequisites.
- A website owner can complete US3 within 30 minutes after prerequisites.
- A supervised fresh test deployment records an accepted consented event.
- Blocking analytics leaves the test website usable.
- A human release owner reviews the fresh-only boundary and validation evidence before go/no-go.
