# Quickstart: validating this feature

Prerequisites: a clean checkout, `pnpm install`, a mock or real console session (see `apps/admin-web/e2e/mock-console.ts`).

## Automated
```bash
pnpm typecheck && pnpm lint && pnpm test
pnpm test:e2e
```
Expected: all green; coverage still above 90%.

## Manual scenarios
1. **Shell**: open the console at 320, 768 and 1280 px; the environment and project controls sit together in the header, no text overlaps, the footer is one line with three items. See [contracts/console-shell.md](contracts/console-shell.md).
2. **Scope**: change environment, then project; visit Overview, Websites, Health; each shows the pair. The Projects page hides the pair.
3. **Projects**: from the project menu use "All projects…", create a project, open it, delete the current one, and confirm the console falls back.
4. **Add website**: paste `Example.com/pricing?x=1/`; the form shows `https://example.com`, name `example.com`, project read-only; save.
5. **Embed**: copy the short embed onto a test page on an allowed origin; events arrive with no other values. See [contracts/embed-defaults.md](contracts/embed-defaults.md).
6. **GitHub path**: guidance states the number of values; a root-level site deploys with the starter workflow unedited.
7. **Check**: remove the SDK file, then the token endpoint, then use a wrong origin; each gives one named next action.
8. **Compatibility**: an embed generated by the previous version still collects.
9. **Health/Access**: Health shows Backend first with the version; the old Backend address opens Health; Access keys is reachable from a website's Share section and absent for non-admins.
