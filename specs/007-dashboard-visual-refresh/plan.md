# Implementation Plan: Dashboard Visual Refresh

**Branch**: `[007-dashboard-visual-refresh]` | **Date**: 2026-09-09 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/007-dashboard-visual-refresh/spec.md`

## Summary

Replace the two-number, website-only overview with a polished project dashboard that can show all websites or one website for a shared 6-hour, 12-hour, 24-hour, 7-day, 30-day, or custom range. The ingestion Worker will immediately reduce trusted request metadata to bounded country, browser, operating-system, device, user-agent-family, and traffic classifications, discard raw headers, and update indexed one-minute D1 aggregates. One admin response will return totals, trends, top-ten rankings, distributions, and completeness without scanning R2.

The React console will adopt Tailwind CSS 4 tokens and Recharts, a responsive accessible time-range popover, a filesystem-backed local theme preference, an original vector Vizoalica logo, and a footer whose version is injected from the root package. The design retains the existing Worker, D1, R2, and loopback console footprint; it adds no paid service or always-running process.

**Project Type**: Monorepo web application with browser SDK, ingestion Worker, local operations API, and React console

**Performance Goals**: One coherent dashboard response in under 2 seconds p95 for a 30-day, quota-bounded project fixture; dashboard trend contains at most 720 hourly or 30 daily points; interaction response remains under 100 ms apart from network fetches

### Post-design re-check

The design does not add a constitutional exception. Minute aggregates are the minimum precision that supports minute-granular custom ranges without raw-event queries. The additional visitor presence and idempotency digests have explicit purposes, 32-day deletion, Worker-only access, project-scoped HMAC derivation, and no UI/API exposure. Small-cell suppression is not added because this is an authenticated owner console with low-volume demo use; privacy instead comes from single-dimension aggregation, top-ten responses, no cross-tabs, and no raw identifiers. Cross-origin visitors are never linked unless the owner supplies an explicitly reviewed common pseudonym.

## Technical Design

### Ingestion and normalization

`worker-adapter.ts` will read `request.cf.country`, `request.cf.botManagement` when present, and at most 512 characters of `User-Agent`. A new source-owned normalizer reduces these values before the ingestion pipeline persists anything. `StoredEvent.event`, R2 serialization, logs, and decisions remain free of raw request metadata. The rollup call receives a separate in-memory `RequestAnalyticsContext` containing only bounded normalized values and an optional aggregation identity.

Only accepted `com.vizoalica.page_view.v1` events update the expanded dashboard. Country uses trusted `request.cf.country`; missing, malformed, or `XX` becomes Unknown and `T1` is shown as Tor Network. The versioned v1 taxonomy bounds browsers, operating systems, device classes, and traffic classes. A recognized browser with no automation signal is Human, strong bot evidence is Bot, and ambiguous input is Unknown. Optional Bot Management signals can strengthen the decision but are never required.

The SDK will persist a consent-eligible anonymous ID in first-party storage under a source-namespaced key, with an ephemeral fallback when storage is unavailable. A reviewed `visitor_id` token claim can provide a common project pseudonym. The Worker uses separate HMAC domains: project-supplied identities omit source so matching values deduplicate across websites, while source-local identities include source so they can never create a cross-site link. The deployment workflow generates the Worker-only `VIZOALICA_ANALYTICS_DIGEST_SECRET` so JWT signing-key rotation cannot silently split unique counts.

### Aggregate storage and correctness

Migration `0005_dashboard_visual_refresh.sql` adds minute totals, independent minute dimension counts, minute visitor-presence digests, an aggregate watermark, and an HMAC event-digest ledger. It keeps migrations `0001`–`0004` intact. One-minute buckets make every supported preset and `datetime-local` custom boundary exact after the UI floors preset end time to the latest complete minute. Trend results are rolled up to hours for ranges through 24 hours and days for longer ranges.

Every ingestion request gets a transient nonce. The D1 transaction first inserts HMAC event digests with that nonce, aggregates only newly inserted rows carrying that nonce, and clears the nonce before commit. Duplicate event IDs therefore cannot increment counts twice. Prepared statements for the request execute through `D1Database.batch`, which Cloudflare documents as a sequential transaction that rolls back on failure. Identical total and dimension mutations are coalesced within the accepted batch before writing.

Dynamic page paths and referrer origins remain bounded by the existing per-source daily event quota, the contract length limits, and 32-day retention. All other dimensions use finite enums; normalized user-agent major versions are integers 0–999. A daily UTC Cron Trigger on the existing Worker removes expired aggregate, presence, and ledger rows in bounded batches. No historical R2 backfill runs. A watermark marks pre-migration portions of a requested range incomplete rather than inventing dimension history.

### Analytics contract and queries

The Worker adds `GET /v1/admin/projects/{projectId}/analytics?start={ISO}&end={ISO}&source_id={optional}`. The loopback API mirrors it as `GET /api/projects/{projectId}/analytics`. `source_id` absent means every non-deleted source plus historical data for disabled sources. The Worker validates minute alignment, `start < end <= now`, a maximum 30-day duration, safe identifiers, project existence, and source ownership before D1 work.

One response contains scope, canonical UTC range, chart interval, totals, both trend series, four rankings, four distributions, and completeness metadata. Project-wide unique users use `COUNT(DISTINCT visitor_digest)` across sources. This deduplicates only matching identities and does not imply that unrelated first-party IDs represent different people. The old website summary endpoint remains as a compatibility adapter for one release while the console moves to the new contract.

Queries select by project, optional source, dimension kind, and half-open minute range. Dedicated source-specific and project-wide composite indexes cover those predicates. Deterministic rankings sort by count descending and label ascending, expose ten entries, and return a remainder count. Distribution responses fold values outside the displayed leaders into Other, retain Unknown, and provide integer counts; one shared presentation function calculates percentages consistently. Query-plan tests must show indexed `SEARCH` operations rather than full table scans for the 30-day fixture.

### Console and visual system

The console will use Tailwind CSS 4 through its official Vite plugin. CSS-first semantic tokens define surfaces, text, borders, focus, status, and chart colors for light and dark themes. Small source-owned primitives cover buttons, cards, selects, inputs, badges, notices, and tables; no general component framework is added.

The overview requests one response per applied scope/range and uses `AbortController` plus a monotonically increasing request generation to prevent stale data from rendering. Components are split into filters, time selector, KPI cards, trend chart, ranked tables, distribution charts, and explicit loading/empty/partial/error states. Recharts renders responsive SVG. Every visualization has a caption and an adjacent semantic table or list with the same values, uses labels/patterns in addition to color, and disables animation for reduced motion.

The compact range trigger displays the active range and local timezone. A native popover contains a preset radio group and a custom form with labeled `datetime-local` inputs. It follows the supplied screenshot's two-column desktop model and becomes one column on narrow screens. Draft values never query until Apply; server validation remains authoritative. Presets use one captured, complete-minute UTC end so all widgets share exactly the same range.

### Preferences, brand, and version

The loopback API adds authenticated same-origin `GET` and `PUT /api/preferences/theme`. It atomically reads/writes a separate `preferences.json` beside the existing local operations config with mode `0600`, an allowlisted schema, and no credentials. Missing or invalid preference data falls back to the system theme; write failure leaves the chosen session theme active and produces a nonblocking status. The document root receives `data-theme` and `color-scheme`; `matchMedia` remains active only until an explicit preference loads.

Original SVG assets will live under `apps/admin-web/public/brand/`: square mark, dark-background horizontal lockup, light-background lockup, monochrome mark, and favicon. `docs/brand.md` records palette, clear space, minimum size, and accessible-name rules. The root `package.json` version is injected by Vite as `__VIZOALICA_VERSION__`; the shared footer renders `2026 | Vizoalica | v{version}` or `vunknown` if injection fails.

## Validation Strategy

- Unit-test the classification taxonomy, precedence, oversized/malformed inputs, special country codes, bot uncertainty, UTC range calculation, percentage rounding, theme parsing, and first-party ID fallback.
- Test that raw UA, IP, bot score/fingerprints, event IDs, visitor IDs, and digests never appear in R2 payload additions, aggregate bindings, logs, errors, or API responses.
- Exercise D1 boundaries at the first included minute and excluded end minute, duplicate event IDs, all-sites and one-site queries, shared and source-local identities, disabled/deleted sources, top-ten ties, Other/Unknown, purge boundaries, and pre-migration incomplete ranges.
- Cover admin authentication, source ownership, project isolation, malformed IDs, future/reversed/overlong/unaligned ranges, same-origin preference access, invalid preference files, and atomic `0600` writes.
- Test the full console flow for scope/range changes, cancelled requests, partial and empty data, theme persistence/failure, footer version, responsive reflow, visible text alternatives, and host-page SDK failure isolation.
- Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm coverage`, `pnpm build`, dependency/security scanning, D1 `EXPLAIN QUERY PLAN` assertions, and the repository's deployment checks.
- Manually verify keyboard-only operation, focus return, screen-reader names/status, both-theme contrast, 200% zoom, 320 CSS-pixel reflow, reduced motion, and the logo at documented minimum sizes.
- Before release, run the required cross-artifact alignment review, complete test cycle, written contrarian QA review, and human release-owner go/no-go review.
